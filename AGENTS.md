# jev-inbox

Chrome MV3 extension, Jev Inbox for Gmail. It shows Gmail's own unread rows at the top of the visible message list on the inbox, other inbox tabs, search results, and labels and other folders, each switchable in the popup, without changing the order of those rows in Gmail's own DOM. Critical rows come first, every classified row carries the label chips whose probability clears the strictness threshold (`threshold`), and a thin status bar above the list shows the unread count, in-flight progress, and errors. Unread rows, and read rows when the popup's "Also classify read mail" (`classifyRead`, off by default) is on, are classified by TypeSafe Jev with the `ai` SDK's `experimental_evaluate`, on Vercel AI Gateway (`createGateway`, `typesafe-ai/jev`) or on TypeSafe's own API (`createTypeSafeAi`, `jev-latest`), chosen in the popup. Classification waits for `privacyAck`, the first-run notice in the popup. A fresh install opens the popup page as a setup tab, the toolbar badge shows `!` until setup is finished, and the Gmail bar offers Finish setup when classification halts for setup. Low-ceremony code by design.

This file is the entry point for agents. Every doc describes the current state of the repo, never its history. The rules in ~/.codex/AGENTS.md apply on top of this file.

File map:

- `src/background.ts`: service worker. Restricts `chrome.storage.local` to trusted extension contexts (`setAccessLevel` `TRUSTED_CONTEXTS`), so the content script cannot read storage. Accepts `classify`, `state` and `openSetup` only from the extension's own content script on `https://mail.google.com`, `test` only from the extension's own pages (the popup or the setup tab), and rejects a `classify` batch over 20 rows or 15 labels. Answers `state` with the content settings and the `crit:` cache entries of the current version, never a key or hint, and forwards each storage change the content script needs to the open Gmail tabs as a `changed` message, reporting a key change as a bare `keysChanged` flag. Handles `classify` and `test` messages, returns `needs_ack` for both until the popup stores `privacyAck`, answers `test` with `needs_ack`, `missing_key` or `provider` plus the HTTP status and never the provider's message, stores `authFailed` with the provider name when a classify batch or the test gets 401 or 403 and removes it when a call to that provider succeeds (trusted contexts only, never forwarded to Gmail), resolves the provider and the matching key, caches classifications in `chrome.storage.local` under a key that includes the provider and the labels hash with a `ts` stamp and the thread's sender name, address, subject and date (`cacheEntry`, for the manage page; the `state` reply, the `changed` messages and the classify reply carry the scores only), fans out to the chosen provider, reports per-row failures with the HTTP status, keeps a good classification when a cache write fails, and prunes the cache to 4000 entries once it passes 5000. On `onInstalled` with reason `install` it opens the setup tab, as it does for `openSetup`; on install, startup and any change to a setup key or `authFailed` it sets the action badge from `setupBadge`, which shows `!` until the notice is accepted, the selected provider has a key and that provider is not in `authFailed`.
- `src/content.ts`: content script. Never touches `chrome.storage`: it loads settings and the cache with a `state` message to the service worker and follows changes through the worker's `changed` messages. Parses the current view from the hash, watches the visible list DOM and its rows' class changes, moves each row to its target layout slot with an inline `translateY` that composes with Gmail's own inline `transform`, critical rows first, synchronously in the observer callback before the next paint, from the classifications it keeps in memory, leaving Gmail's DOM order and every row's position in it untouched, extracts and dispatches the unread rows that still need classification, and the read rows too when `classifyRead` is on (one `classifiableKey` gate for dispatch, counts, chips and matching; read rows stay below unread ones), writes label chips and loading dots inside the rows, makes each chip and the Critical badge a filter button that, with the matching buttons in the bar, shows only the loaded rows that carry it (non-matching rows are ranked last and marked `data-gc-hidden`), stops every pointer and Enter or Space event on those buttons at window capture so none reaches Gmail, keeps the filter across re-renders and Compose and clears it on another list, renders the status bar with its progress line, reads Gmail's own theme from the list's effective background on every pass and on head, `html`/`body` class or style and color-scheme changes and writes it as `data-gc-theme` on the bar and every chip slot, shows a provider failure in the bar as the text `rowFailureText` maps from its status, halts on `needs_ack`, auth failures, or a missing key until the popup fixes it, showing no loading dot and no `retrying` on unclassified rows while halted (`retrying` only when a retry is scheduled), and shows a Finish setup button (styled like Clear, isolated like the filter buttons) that sends `openSetup`, animates a row that moves after a classification arrives with a transition between its old and new offset, restores each row's own inline styles, re-measures the offsets when a row changes height, backs off failed rows through a map that outlives the rows, and restores the list when the route or the list changes. The bar's count, progress text and error sit in a `span.gc-live` with `role="status"` and `aria-live="polite"`, rebuilt only when that text changes, with the filter controls outside it; the loading dot is `role="img"` named `Classifying`.
- `src/theme.ts`: `parseColor` (the `rgb()`, `color(srgb …)` and hex forms), WCAG `contrastRatio`, `composite`, and `themeFromBackgrounds`, which picks light or dark from the backgrounds from the list up.
- `src/a11y.ts`: the labels editor's accessibility decisions, DOM-free: `deleteLabelText` (the trash button's name, `Delete label Visa`, `Delete unnamed label 2` for an empty name, `Confirm delete ...` while armed) and `focusAfterDelete` (the next label, else the previous one, else null for Add label).
- `src/status.ts`: the halted and setup decisions, DOM-free: `pendingRow` (loading dot, `retrying`, or nothing while halted), `popupStatusText` (the popup's status line, in priority order), `isGmailUrl`, `canTestConnection` and `testHintText` for the Test button, and `isAuthRejection` and `nextAuthFailed` for the worker's `authFailed` record.
- `src/filter.ts`: the row filter: `RowFilter` and its `data-gc-filter` token, `isCritical` and `shownLabels`, the predicate that decides both which chips a row shows and whether it matches a filter, `filterOptions` for the bar, `filterRoute` (the route without the open thread or the query), and `filterNote`, the bar text that says the filter covers loaded rows only.
- `src/errors.ts`: the one place a provider failure becomes user-facing text: `providerErrorText` maps an HTTP status (401/403, 429, 5xx, other 4xx, none for network failures) to short plain text, `rowFailureText` picks the failure a classify batch shows in the Gmail bar, and `testResultText` turns a `test` result into the popup's text. The provider's own message is never shown.
- `src/triage.ts`: the manage page's logic, DOM-free: `triageThreads` (the cache entries of the current labels and provider with their stored sender, top label above the threshold, and a count of entries saved without a sender), `filterThreads` (label, no label, urgency range, sender or subject text), `groupThreads` (by label in label order, then by sender, merged across letter case, with counts and the latest subject), `isSearchableEmail`, `senderQueries` (`from:(a OR b)` searches, with `in:inbox` when asked, split at `GMAIL_QUERY_MAX`, 1500 characters, the known Gmail filter limit, not measured live against the search box), `gmailSearchUrl` and `gmailAccounts` (the `mail/u/N` numbers of open Gmail tabs).
- `src/manage.html` and `src/manage.ts`: the manage page, opened in a tab by the popup's Manage button. Reads `chrome.storage.local` once when it opens, renders the groups with sender and pick-all checkboxes, and shows Open in Gmail links (numbered when the search is split) for the account picked from the open Gmail tabs. It never writes storage and never changes mail.
- `src/jev.ts`: `classifyEmail` and `testConnection`. Both build and run one Jev evaluation call on the chosen provider: critical, urgency, and one boolean question per label for a row, one boolean question on a fixed dummy state for the popup's connection check.
- `src/shared.ts`: shared types, `Provider`, settings defaults and key lists, label config, validators, `labelIssue`, `labelIssueText` and `labelsToSave` for the labels editor, `labelsHash`, `cacheVersion`, `threadKey`, `routeKey`, view and hash parsing, and `contentState` and `contentChanges`, which pick what the service worker hands the content script.
- `src/requests.ts`: `parseRequest`, the service worker's sender check and message validation.
- `src/setup.ts`: first-run decisions: `SETUP_PAGE` (`popup.html?setup=1`), `setupBadge` (`!` and "Jev Inbox: finish setup" while the notice is not accepted, the selected provider has no key, or a 401/403 was seen), `opensSetupOnInstall`, `isSetupPage` and `touchesSetup`.
- `tests/`: unit tests, bundled with esbuild and run with `node --test` by `npm test`.
- `src/popup.ts`: popup logic. Saves the provider, each provider's key plus a `...Hint` of its last four characters, enabled, the Strictness slider (stored as `threshold`), the first-run acknowledgement, the Show on view toggles, "Also classify read mail", and the label list, where each complete label saves on its own and an incomplete one stays in the editor with `aria-invalid` and an inline message linked through `aria-describedby` (an incomplete edit of a saved label keeps its saved version until fixed); never reads a stored key back, showing "Key saved, ends in ..." with Replace and Remove instead; shows a status line from `popupStatusText`: Paused, the notice, a missing key, a key rejected on the last call (`authFailed`, followed live through `chrome.storage.onChanged`), or whether the active tab is Gmail (`chrome.tabs.query`, readable through the `mail.google.com` host permission); runs the connection test, disabled until the notice is accepted and a key is saved or typed, saving a typed key before it sends `test`, and shows its result through `testResultText`; clears `authFailed` when that provider's key is saved or removed; clears the classification cache after a Confirm clear step; adds `setup` to `<html>` on `?setup=1` and `paused` to `<body>` while the switch is off. Names each label's trash button with `deleteLabelText` and updates it as the name is typed, focuses the new name field after Add label and the `focusAfterDelete` target after a confirmed delete, and empties the Saved indicator once it fades so its live region announces the next save. Its Manage button opens the manage page in a tab.
- `src/popup.html`: popup markup (`lang="en"`) and its inline styles and theme tokens, including the labels editor, the three-bullet first-run notice, the welcome and centred card of the setup tab, and the dimmed paused sections. The Saved indicator and the test result are `role="status"`, and each label's inline message (created in `popup.ts`) is `role="alert"`. `--field-border`, `--switch-track`, `--switch-border`, `--switch-knob` and `--switch-knob-on` give input borders, switch tracks and the switch knob at least 3:1 against what sits next to them in both color schemes (WCAG 1.4.11, checked by `tests/theme.test.ts`).
- `src/section.css`: styles for the status bar, its filter buttons, the Critical badge, the inline label chips with their pressed and focus states, and the `data-gc-hidden` rows, and the `gc-live` region, with explicit light tokens and dark overrides under `[data-gc-theme='dark']`, every text pair at WCAG AA, and red reserved for Critical: no label hue's text, tint or pressed fill sits within 30 degrees of Critical's in either theme (hue 3 is olive). `tests/theme.test.ts` checks both.

## Build and load

1. `npm install`
2. `npm run build`: bundles to `dist/` (esbuild) and copies `manifest.json`, `popup.html`, `section.css`, `assets/`. `npm run watch` rebuilds on change.
3. Chrome: chrome://extensions, enable Developer mode, "Load unpacked", select the `dist/` folder.
4. Loading the extension opens the setup tab (the popup page, also reachable from the toolbar): accept the first-run notice, pick the provider under "Connection", paste its API key, leave the switch on, pick the views under "Show on", add labels if wanted. Gmail: mail.google.com shows the unread rows of the visible list at the top, in place, and shows the status bar on the enabled views.

`npx tsc --noEmit` typechecks. Calls go to `https://ai-gateway.vercel.sh/v4/ai` or `https://api.typesafe.ai/v1`; both keys live in `chrome.storage.local`, which the service worker restricts to trusted extension contexts, and only the service worker reads them. The content script gets the named settings and the `crit:` cache entries from the worker's `state` reply and its `changed` messages.
